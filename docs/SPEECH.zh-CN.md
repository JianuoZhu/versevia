# 无原生字幕时生成字幕（纯扩展实验性功能）

不需要 audio bundle、Python、FFmpeg、Node 或本地辅助程序。用户只安装扩展；语音识别仍调用自己配置的服务，不等同于离线识别。

## 更新和使用

1. 在 Chrome 扩展管理页重新加载已有扩展，再刷新 YouTube。扩展 ID 无需手动配置。
2. 播放几秒，让扩展观察到播放器的 SABR 音频请求；之后可以暂停。若有多个配音，先在 YouTube 设置中选定所需音轨。
3. 先点击 **Test browser audio · no speech API**。它仅取当前位置附近 5 秒并在浏览器解码，报告成功或具体错误，不提交语音接口、也不写字幕缓存。
4. 点击 **Configure speech service** 配置语音接口。服务必须支持 `verbose_json` 及带 `start/end/text` 的 `segments`；翻译配置独立。
5. 选择附近 5 分钟或整段视频，勾选音频发送同意项，再点 **Generate from video audio**。直链下载首次会申请 googlevideo.com 访问权限，不请求 nativeMessaging。

## 实现

- 优先通过 SABR 请求确认播放器当前选择的音轨，再独立请求目标时间段，通过 UMP 协议取出初始化段和音频段。无需让视频播放到目标时间。
- 未取得 SABR 元数据时，只允许单一语言的独立音频 URL 分支，限制 15 分钟 / 20 MB，在浏览器解码。多语言视频不再猜测原音轨。
- SABR 当前支持播放器请求中匹配的 WebM 音轨；将原始分片在扩展 offscreen 页面解码成 16 kHz 单声道 WAV，再提交语音接口。
- 每段约 30 秒，前后各带最多 1 秒上下文；优先处理当前播放位置，每段完成立即显示并缓存。识别不改变视频的播放位置、暂停状态和速度。
- 不再自动回退到本地 helper。仓库保留旧版 native 源码供参考，当前版本不调用它，安装 audio bundle 对本版无必要。

## 语言处理与分块

Match video 现在优先使用实际音轨语言：英语轨传入 `language=en`，日语轨传入 `ja`。只有音轨缺少语言元数据时才让识别服务检测；识别结果会统一成语言代码。手动指定语言若与当前音轨冲突，会报错，避免生成另一个配音的字幕。

若服务返回的语言与请求语言不符，任务停止，不显示或缓存该段；英语请求返回大量西里尔字母文本时也会拒绝。这里的检测是防止明显错配的保护，并不能保证模型每个字都正确；英语视频中长段引用另一种语言也可能触发停止。

音频测试结果包含语言和音轨 ID，可用于检查是否选择了正确的原声或配音。

分块是当前实现的工程选择：先返回当前位置的结果，限制内存及单次请求大小，支持分段缓存和取消。独立 URL 分支仍可下载完整音轨再切分；SABR 分支目前按区间取音频。整段音轨并非必然识别更差，分块本身会减少跨段上下文，所以当前增加了两侧各最多 1 秒重叠；约 30 秒不是语音服务的硬性时长限制。

## 限制和隐私

这是实验性兼容实现，不保证所有视频或账号成功。YouTube 的非公开 SABR 协议、授权、请求形态可能改变；AAC-only、在 Worker 内发送且未观察到的请求、授权过期、403、服务器要求刷新等都会明确失败。出现授权错误先播放几秒重试；更新扩展后必须刷新视频。

普通视频最长 4 小时。SABR 每次请求区间最多 32 秒，单个响应和累计音频均限制 8 MB；每个区间最多 8 次网络请求、60 秒。只有完整连续的音频段通过时间轴校验后才会提交 ASR；不补造缺失的音频或字幕时间。

不支持直播、广告和 DRM 内容。切换视频、关闭标签页、禁用扩展、修改语音或源语言配置会取消任务。手动取消会终止剩余请求，服务已接收的识别请求仍可能计费。

播放器的临时 SABR 地址、PO token 和请求上下文仅保留于该页面内存，不发送给语音服务，不写日志或持久存储；语音 API key 留在扩展可信上下文，不进入 YouTube 页面。仅选中区间的 WAV 发送给语音服务。协议代码随扩展打包，不远程下载或执行 YouTube 播放器代码。

字幕按视频、实际音轨 ID、请求源语言、语音 endpoint/model 和区间缓存 30 天，和译文共用有容量上限的本机 IndexedDB。读取缓存前确认当前音轨；全部命中时不下载音频也不调用 ASR。切换配音后清除页面上的旧生成字幕，并取消该页旧任务。1.4.0 的生成字幕缓存不再复用，更新后需重新生成；无需清空翻译缓存。

Manual recording fallback 保留 15/30/60 秒标签页录音；仅这个备用方式仍要求 1× 连续播放。

## 验证方式

`npm.cmd run verify` 运行协议、边界、任务生命周期、缓存、解码和 UI 自动化测试。`npm.cmd run lab` 后打开 `/lab/sabr-decode.html` 可验证真实 Chrome 对非零时间戳 WebM 的解码；音频为合成测试音，不代表 YouTube 网络测试。

实际 YouTube 验证使用扩展的 **Test browser audio** 按钮。自动化模拟通过不能代替真实播放器授权验证；完整结果见 VERIFICATION.md。

用户已反馈真实 YouTube 测试成功：从 12.8 秒处解码了 5 秒音频，检测到音频信号，未调用语音接口，也未安装 audio bundle。这证明当前播放器会话的纯扩展取音频与解码链路可用；整段处理、跨视频兼容性及实际字幕识别质量尚待验证。
